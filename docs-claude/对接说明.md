# 妈妈小店 · 前端对接说明（给 Miku）

## 1. 这个包是什么
完整的**买家端 + 妈妈后台前端**（原生 WXML/WXSS/JS），符合需求书 v2 的技术约束：不用任何框架、不引第三方库、零付费资源。
包里只有 `miniprogram/` 和 `docs/`。**项目骨架里的 `project.config.json`、云函数、`scripts/` 都不在包内，仍归你。**

用法：用本包的 `miniprogram/` **整个替换**骨架里的 `miniapp/miniprogram/`，然后照常跑 `node scripts/preview.js` 出预览码即可。

## 2. 两种运行模式（改一个文件）
`miniprogram/utils/config.js`

| 配置 | 说明 |
|---|---|
| `envId` | **留空 = 演示模式**：数据存在手机本地，下单、转账提示、妈妈后台全流程都能走通，**不依赖云开发**，owner 现在就能扫码体验。填了环境 ID = 走云函数。 |
| `payMode` | `'transfer'`（一期）/ `'wxpay'`（二期）。页面流程不用改。 |
| `contact` | 妈妈手机号 / 微信号。留空则对应入口不显示。 |
| `demoAdmin` | 仅演示模式：是否显示“妈妈后台”入口。 |

> 需求书说环境 ID 填 `app.js`，这里集中到了 `config.js`，`app.js` 会自动读取。

## 3. 接云开发：一个云函数 `shop`
所有页面只通过 `utils/api.js` 取数。云端只需要部署**一个**云函数 `shop`，按 `event.action` 分发。
返回格式统一：成功 `{ ok: true, data }`，失败 `{ ok: false, msg: '给用户看的中文提示' }`。

| action | 入参 | 返回 data | 备注 |
|---|---|---|---|
| `login` | — | `{ openid, isAdmin, nickName }` | 按 openid 查/建 `users` |
| `listProducts` | — | 商品数组 | 仅 `onSale=true`，按 `createTime` 倒序 |
| `getProduct` | `id` | 商品 | **含下架商品**（详情页、后台编辑页共用） |
| `getAddress` | — | 地址或 `null` | 默认地址 |
| `saveAddress` | `addr{name,phone,detail}` | 地址 | 设为默认 |
| `createOrder` | `items[{productId,qty}]`, `address`, `remark` | `{ _id, orderNo, total }` | **见下方“下单安全”** |
| `listOrders` | — | 当前用户的订单 | 倒序 |
| `getOrder` | `id` | 订单 | 仅本人或管理员 |
| `adminListOrders` | — | 最近 100 单 | 仅管理员 |
| `adminOrderAction` | `id`, `action`, `expressNo` | 订单 | `confirmPaid`(0→1) / `ship`(1→2，写 expressNo) / `complete`(2→3)；状态不对要报错 |
| `adminListProducts` | — | 全部商品（含下架） | 仅管理员 |
| `adminSaveProduct` | `product{_id?,name,price,stock,images,desc,onSale}` | 任意 | 无 `_id` 为新增；`price` 为分 |
| `adminSetOnSale` | `id`, `onSale` | 任意 | 仅管理员 |
| `orderPrepay`（二期，独立函数） | `orderId` | `{timeStamp,nonceStr,package,signType,paySign}` | 即需求书 §7 |

**所有 `admin*` 必须在云函数里校验 `users.isAdmin`**，前端的 `guard.js` 只是友好提示，不是安全措施。

### 下单安全（重要）
前端 `createOrder` **只传 `productId` 和数量**。云函数必须：
1. 按库里的价格重新计算 `total`（绝不信前端传的价格）；
2. 校验商品存在、`onSale`、库存够，不够就 `{ok:false, msg:'「xx」库存不足，只剩 N 件'}`；
3. 扣库存（建议用事务/`inc`，防超卖）；
4. 生成短订单号 `orderNo`，写入 `status:0`。

### 对数据模型的 3 处小补充
- `orders.orderNo`（string）：**短订单号**，格式 `MMDD-序号`，如 `1009-003`。买家转账备注要写它，`_id` 太长没法写。
- `orders.remark`（string）：买家留言。
- `orders.items[].image`（string，可空）：下单时的商品封面，订单页展示用。
金额一律是**分**，前端展示时才换成元（`utils/format.js`）。

### 云存储权限
商品图是妈妈上传的 `cloud://` 文件 ID，买家要能看。云存储权限请设为 **“所有用户可读，仅创建者可写”**，否则买家端图片会显示成占位图。

## 4. 二期切微信支付
`config.js` 里 `payMode: 'wxpay'`，并部署 `orderPrepay`。付款页会调用 `api.prepay(orderId)` → `wx.requestPayment`；转账说明会自动换成“微信支付”按钮。订单状态由支付回调改成 1。

## 5. 真机请重点看这 6 处（我没法在微信开发者工具里实跑）
1. **玻璃效果**：悬浮 tabBar、顶部导航、详情页底栏、弹层用了 `backdrop-filter`。iOS 效果最好；不支持的安卓会自动退回不透明白底，不影响使用。
2. **首次编译**：样式里用了 `@supports` 和 `env(safe-area-inset-bottom)`，如果开发者工具报样式错误，把报错发回来。
3. **自定义 tabBar**：`app.json` 里 `tabBar.custom = true`，实现在 `custom-tab-bar/`。各 tab 页 `onShow` 里用 `utils/tab.js` 同步选中态和购物车角标。
4. **图标**：`images/icons/*.svg` 用 `<image>` 加载。如果真机上看不到图标，说明基础库偏旧，需要把 SVG 换成 PNG。
5. **从微信导入地址**：`wx.chooseAddress` 个人主体账号可能不可用，已做失败回退为手动填写。
6. **演示模式的照片**：妈妈在演示模式里选的照片是临时路径，重启小程序后会失效（接了云开发后是正式文件，没有这个问题）。
